# blqsort experiments

The measurements behind [blqsort](https://github.com/dlm/blqsort), a
branchless quicksort for Go. This is a separate repository that depends on
a released version of blqsort (see `go.mod`), so results name the exact
library version measured, and the libraries compared against don't become
dependencies of blqsort itself.

## Running

`./run-benchmarks.sh` runs the full careful suite (roughly half an hour)
and writes the results plus a record of the environment (CPU, OS, Go
version, blqsort version, commit of this repository, pinning, power
state) to `results/<host>-<arch>/`. Plug laptops in: on battery the script
refuses to run (override with `ALLOW_BATTERY=1`), since battery power
settings made every benchmark about 20% slower on the Intel machine. The rest of this section
explains running parts by hand.


Benchmarks are sensitive to CPU frequency scaling and, on hybrid CPUs, to
which core they land on (unpinned runs varied by up to 30%). Pin to one
performance core and use one OS thread:

```sh
go test -c -o exp.test .
GOMAXPROCS=1 taskset -c 2 ./exp.test -test.run '^$' -test.bench BenchmarkLibraries -test.benchtime=3x
```

(Check which cores are performance cores, e.g. `/sys/devices/cpu_core/cpus`
on Intel hybrid CPUs.) The pattern tables are long-running tests that print
tables with `t.Log`; they are skipped unless `BLQ_PATTERNS=1` is set:

```sh
BLQ_PATTERNS=1 GOMAXPROCS=1 taskset -c 2 ./exp.test -test.run TestPatternTimes -test.v
```

`go test .` runs the correctness tests of everything here (generated
specializations, the branchless pdqsort, the library comparisons).

## Experiments

| What | How | Question |
|---|---|---|
| Other libraries, random data | `BenchmarkLibraries` | blqsort vs `slices.Sort`, a radix sort ([zermelo](https://github.com/shawnsmithdev/zermelo)) and [sorty](https://github.com/jfcg/sorty) (single-threaded), int64 and float64, 1K–10M |
| Other libraries, input shapes | `BenchmarkLibraryShapes` | the same on random, few-unique, sorted, reversed, `i%8`, `i^0xcccc` at 1M |
| Stdlib benchmarks | `BenchmarkGoStdlib` | equivalents of the `sort` package benchmarks (their "unsorted" inputs are structured) |
| Pattern matrix | `TestPatternTimes` | Bentley-McIlroy distributions × modifications, blqsort vs `slices.Sort` |
| Branchless pdqsort | `BenchmarkContenders`, `TestPatternContenders` | the stdlib pdqsort with Orson Peters' branchless block partition (`blockpartition.go`) vs blqsort; `pdq-go` is the same generated pdqsort with Go's partition as a control |
| Size crossover, fresh vs repeated inputs | `BenchmarkCrossover` | where blqsort starts to win, and how much sorting the same input repeatedly (as most benchmarks do) lets the branch predictor memorize small inputs |
| Small-path threshold | `BenchmarkThreshold` | whether blqsort's switch from its small path (up to 1,025 elements) to its large partition shows as a step, fresh inputs around 1,025/1,026 |
| Run-length crossover | `TestRunCrossover` | how many sorted runs it takes for pdqsort's adaptivity to win |
| API shapes | `BenchmarkAPI`, `BenchmarkBranchlessCmp` | `SortFunc` vs `SortLess` vs `SortByKey`, branchy vs branch-free comparators, and PGO (see below) |
| Specialization | `BenchmarkSpecialized` | code generated for one type (`*_gen.go`) vs function values, by element size (8–64 bytes) and with two keys (branchy vs branch-free) |
| Strings | `BenchmarkStrings` | `cmp.Ordered` strings, with and without a common prefix |

PGO: build with a profile of the API benchmarks to see devirtualized
comparator calls, e.g. `-test.cpuprofile api.pprof` on a `BenchmarkAPI` run,
then `go test -c -pgo=api.pprof`.

## Generated code

Files named `*_gen.go` are generated by `go generate` (`go run ./gen`):
specializations of blqsort and of the stdlib pdqsort for the record types
in `types.go`, and copies of the stdlib pdqsort for ordered types. The
blqsort source comes from the version in `go.mod` (via the module cache),
so the generated copies match the library being measured; run
`go generate` after changing that version. `internal/codegen` is a copy of
blqsort's code generator, free to evolve separately. `blockpartition.go`,
`pdqsupport.go` and `types.go` are hand-written.
